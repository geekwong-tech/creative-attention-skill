# 记录与审阅

## 轻量记录

可用 Markdown、用户既有笔记格式或适用工具。不要为了这些字段让用户重填已知信息。来源使用任务内匿名标识即可；有保密限制时私下保存定位信息，不把原图或内部资料发布。

示例结构（数量按证据决定）：

```markdown
依据：观察记录 case-A / v1，来源为用户描述（未核验原图）
提炼：v1；方法 M1 / v1；采用：待选择

结论：识别到一个主候选、一个具体辅助方法；效果未测。
M1 名称｜一句操作｜本例作用｜自检建议

<details>
<summary>证据、方法与边界</summary>

观察 O1：……
本例解释：比较假设……；具体操作……；可能感知……；疑问可无。
相关性：……；移除检查：……；替代解释：……。
独立方法：素材角色……；操作和必要关系……；条件与边界……。
自检：可保留/需修改/证据不足/普通表达；理由与观察定位。
迁移草案（如请求）：……；需核实的目标事实……。

</details>

组合配方（可选）：M1 v1 + M2 v1，以……关系配合；不是必须全选。
采用记录：用户明确选择的具体方法/配方和版本、时间、目标位置；或待采用。
```

显示支持关系时避免循环。一个辅助可以直接服务“可读性/比较/行动入口”而无需捏造主创意。移除同一材料上的一个关系后，另一个仍成立，可分别评估；只有操作和功能同义才合并。

## 内容版本与状态

自检、独立审阅、用户采用、实际写入和实际效果分别记录，不能相互代替。用稳定标题加递增版本和内容摘要即可绑定；有自动化需求时才使用内容哈希，不伪造哈希或工具记录。

依据、方法、配方成员/关系发生修改时，生成新版本，将针对旧内容的检查和采用标为“仅适用于旧版，新版待核对”。历史资产保留；新来源可追加自己的案例角色，不覆盖共享方法。用户先前对具体已展示版本的明确采用可复用，不反复索要许可；笼统“以后自动入库”不能推定为任意外部发布权。

证据不足候选不能作为有依据的方法采用；若用户仍希望探索，另标“无证据的创作假设”。需修改候选修正后可由用户明确核对采用，不要求模型为自己的改稿再盖章。

## 逐条质量 rubric

| 检查面 | 通过所需证据 | 不通过时处理 |
|---|---|---|
| 支持 | 观察确实支持所述关系，原句和推断可分 | 补观察或缩小结论，引用编号存在不等于含义正确 |
| 机制 | 主：相对明确比较假设的具体偏离；辅：明确对象/关系及具体功能 | 仅“反差、醒目”需改写；不强造主 |
| 复用 | 通用素材角色、可执行操作、成立条件；换对象仍保留关系 | 物件清单或同义改名需重新抽象 |
| 区分 | 不同方法有不同操作/作用；共同材料不强行合并 | 同义项合并，必要相互依赖写入配方 |
| 相关与真实 | 服务议题，迁移待核实事实单列，注意假设不作实测 | 无关怪异或虚构事实不保留为合格候选 |

每项给短理由，不求总分。关键事实错误不能被其它优点抵消；方法名字不同或输出更短不自动算错。角色有合理分歧时保留条件及理由。语义可复用不等于已采用，采用不等于实际效果验证。
